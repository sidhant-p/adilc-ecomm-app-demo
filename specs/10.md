# Spec: Implement Ecomm Login Module

> Work item: github#10 · Correlation: `wi-github-10`
> Author: Copilot CLI · Status: Draft

## Purpose / Scope

This spec defines the implementation of a full-stack login module for the e-commerce application. It provides user registration, login authentication using JWT, stateless logout, and a protected dashboard route displaying the current user's profile information.

## In scope

- User registration endpoint and page accepting full name, email, and password.
- User login endpoint and page validating credentials and returning a JWT token.
- Logout endpoint and client-side token discard functionality.
- Current user info endpoint (`GET /auth/me`) requiring Bearer authentication.
- React frontend pages: `RegisterPage`, `LoginPage`, `DashboardPage`.
- Client-side auth utilities: `ProtectedRoute`, Axios interceptor for 401 responses, and localStorage token management.
- Backend FastAPI app with SQLite storage, bcrypt password hashing, and JWT creation/verification.

## Out of scope

- Password reset or "forgot password" functionality.
- Social / OAuth single sign-on (SSO).
- Email verification workflow.
- Role-based access control (RBAC).
- Production deployment or containerization configurations.

## Requirements

1. The backend must provide `POST /auth/register` to create a new user with `full_name`, `email`, and `hashed_password`, returning HTTP 201 on success or HTTP 409 if the email is already registered.
2. The backend must provide `POST /auth/login` to authenticate email and password, returning an HTTP 200 with a JWT access token valid for 30 minutes.
3. The backend must provide `POST /auth/logout` as a stateless endpoint for client logouts.
4. The backend must provide `GET /auth/me` requiring a valid Bearer token and returning current user details (`id`, `email`, `full_name`, `created_at`).
5. All user passwords must be hashed using bcrypt before persisting to the SQLite database.
6. The frontend must provide `RegisterPage` at `/register` to submit user credentials to `POST /auth/register` and redirect to `/login` upon success.
7. The frontend must provide `LoginPage` at `/login` to submit credentials to `POST /auth/login`, store the JWT in `localStorage`, and redirect to `/dashboard`.
8. The frontend must protect `/dashboard` via a `ProtectedRoute` component that checks `localStorage` for a token and redirects unauthenticated users to `/login`.
9. The frontend Axios client must include an interceptor that handles HTTP 401 responses by clearing `localStorage` and redirecting to `/login`.
10. Forms on the frontend must display inline error messages for validation errors, bad credentials, and duplicate email signups.

## Design

### Monorepo Structure

- `frontend/`: React + Vite application running on port 5173.
  - `src/pages/`: `LoginPage`, `RegisterPage`, `DashboardPage`.
  - `src/components/`: `AuthForm`, `ProtectedRoute`.
  - `src/api/`: Axios client with JWT request/response interceptors.
- `backend/`: Python FastAPI application running on port 8000.
  - `main.py`: App initialization and CORS setup (`http://localhost:5173`).
  - `routers/auth.py`: Authentication endpoints (`/register`, `/login`, `/logout`, `/me`).
  - `models.py`: SQLAlchemy `User` model.
  - `schemas.py`: Pydantic request/response schemas.
  - `auth.py`: Password hashing (passlib/bcrypt) and JWT token creation/verification (jose/PyJWT).
  - `database.py`: SQLAlchemy SQLite engine and session management.

## Data flow

1. Registration: `RegisterPage` -> `POST /auth/register` -> `schemas.UserCreate` -> `bcrypt.hash()` -> `models.User` saved to SQLite (`ecomm.db`) -> HTTP 201.
2. Login: `LoginPage` -> `POST /auth/login` -> `schemas.UserLogin` -> `bcrypt.verify()` -> `create_access_token()` -> HTTP 200 `{ "access_token": "...", "token_type": "bearer" }` -> client saves token to `localStorage`.
3. Protected Access: `DashboardPage` -> `GET /auth/me` with `Authorization: Bearer <token>` -> `auth.get_current_user()` decodes JWT -> returns `UserResponse` schema -> UI renders user profile.
4. Logout: `DashboardPage` Logout button -> `POST /auth/logout` -> client removes token from `localStorage` -> redirect to `/login`.

## Error handling

- Validation error (missing or malformed fields): Backend returns HTTP 400 `{ "detail": "..." }`.
- Authentication error (invalid credentials or expired token): Backend returns HTTP 401 `{ "detail": "..." }`.
- Duplicate registration (email already exists): Backend returns HTTP 409 `{ "detail": "..." }`.
- Global client interceptor catches HTTP 401 errors, purges `localStorage`, and navigates user to `/login`.

## Testing

- Backend unit/integration tests for `/auth/register`, `/auth/login`, and `/auth/me` endpoints using `httpx` and FastAPI `TestClient`.
- Verification of bcrypt password hashing and JWT token expiration handling.
- Frontend component testing or manual smoke testing for navigation flow and protected route redirection.
